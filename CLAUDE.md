# Klinik Asistanı

## Proje Özeti
Fizyoterapi klinikleri için multi-tenant muayene/klinik yönetim SaaS'ı; Asistan Merkezi çatısı altında. Kapsam: hasta kaydı, randevu/çizelge, muayene odalarında tablet ile anlık hasta-işlem gösterimi, seans notu + 2D vücut haritası, cari/paket/ödeme, personel (izin-puantaj-hakediş), hasta portalı, QR self-servis akışları, mesajlaşma (SMS/WhatsApp/Mail) ve Paraşüt.

İş modeli: klinik büyüklüğüne göre kademeli SaaS (1-3 / 4-8 / 9+ terapist), beyaz etiket opsiyonu düşünülüyor. İleride React Native ile terapist+hasta mobil uygulaması.

**İlgili dosyalar**: `app/(app)/panel/personel/CLAUDE.md` (personel modülü) · `docs/DESIGN.md` (tasarım spesi) · `docs/TUZAKLAR.md` (tuzakların gerekçesi) · `docs/DEGISIKLIK-GUNLUGU.md` (tur-tur geçmiş) · **`docs/CLAUDE-ARSIV-2026-10-26.md`** (bu dosyanın küçültülmeden önceki TAM hâli: tüm tur notları, doğrulama ayrıntıları, migration geçmişi — oturumda okunmaz; bir alana dokunurken ayrıntı gerekirse oradan `Grep` ile ara).

## Stack ve Altyapı
Standart Asistan Merkezi stack'i + **Next.js 16** (16.3.8 sabit; App Router, React 19, `useActionState`; oturum yenileme kök `proxy.ts`'te) + Tailwind v4. Vercel (Frankfurt), Cloudflare DNS, Supabase.

- **Paraşüt**: şema/kuyruk hazır, **gerçek hesap ve API kimliği YOK** — `faturaTetikle` sabit "bağlantı kurulmadı" döner, `fatura.durum='bekliyor'` kalır.
- **Mesajlaşma**: SMS/WhatsApp/Mail TEK merkez ucundan (Asistan Merkezi `/api/v1`, ayrı proje) — `lib/mesaj/merkez-client.ts` ("Ortak çekirdek" bölümü fitness'la BİREBİR aynı; test `merkez-client.test.ts`): `X-Api-Key` + `X-Imza` HMAC, `disKullaniciId = klinik_id`, 404'te otomatik `/kullanici/senkron`, `mail→eposta`, 202 `askida` başarı sayılır, paket fiyatı merkezden kuruş gelir → TL. Env `MESAJ_MERKEZ_BASE_URL`/`MESAJ_MERKEZ_API_KEY` henüz GİRİLMEDİ (gönderim fiilen çalışmaz, kuyruğa yazılır). Kuyruk boşaltma: merkez zamanlayıcısı `/api/cron/mesaj-kuyruk-isle`'ı 5 dk'da bir Bearer `CRON_SECRET` ile çağırır; `vercel.json`'a eklenmesi gerekmez.
- **Cron** (`vercel.json > crons`): `personel-donem-otomatik-kapat` (ayın 1'i 03:00 UTC; son 3 ay, idempotent RPC, 8'li eşzamanlı, `maxDuration` 300) · `resmi-tatil-guncelle` (1'i 04:00 UTC) · `audit-log-bolum-olustur` (1'i 02:00 UTC). `mesaj-kuyruk-isle` ve `kredi-senkron` route'ları kodda var ama `crons`'a BİLİNÇLİ eklenmedi. Yetki: `lib/cron-yetki.ts` (Bearer `CRON_SECRET`, sabit zamanlı). Hobby planında 5 dk sıklık reddedilebilir (plan teyit edilmedi).
- **PDF**: `puppeteer-core` + `@sparticuz/chromium`, `lib/pdf/browser.ts`. Şablonlar Tailwind KULLANMAZ — düz TS string + inline style (`lib/pdf/form-sablon-cekirdegi.ts`, `pdf-yardimcilari.ts`). Canlı Vercel'de çalıştığı teyit edilmedi.
- **Tablet**: kiosk, Supabase Realtime, salt-okunur. Bağlantı toleransı (`tablet-ekrani.tsx`): "Çevrimdışı" rozeti kanal durumu/`navigator.onLine`'dan; yeniden bağlanınca liste sessizce tazelenir + 5 dk güvenlik yenilemesi. Gerçek PWA/sayfa önbelleği YOK (bilinçli). Çevrimdışı yedek sayfa: `public/tablet-offline.html` + TEK amaçlı network-only service worker `public/tablet-sw.js` (kapsam `/panel/tablet/`, yalnız `navigate` ağ hatasında devreye girer, hiçbir oturumlu içerik önbelleğe girmez); `proxy.ts` matcher'ı iki dosyayı auth'tan muaf tutar. SW tablet sayfası en az bir kez çevrimiçi açılmadan kurulmaz. **Tarayıcıda denenmedi.**
- **Kart ödemesi** (İyzico/Stripe + 3DS): henüz kurulmadı.

Eski v1 `audit_log_yaz()` klinik CASCADE silmede var olmayan klinik'e yazıp silmeyi engelliyordu — düzeltildi.
- **Diğer**: `audit_log` · `bildirim_log`/`hasta_iletisim_log` · `destek_talebi` · `anket_yaniti` · `oturum_kilidi` (bkz. Oturum) · `hiz_siniri_sayac` · `islem_kategori` (UI yok) · `hasta_hedef`/`v_hasta_karsilastirma` (UI kaldırıldı).
- **View**: `v_hasta_ozet`, `v_hasta_detay_ozet`, `v_hasta_cari_ozet`, `v_hasta_karsilastirma`, `v_personel_bilgi_durumu`, `v_personel_izin_bakiye` + `mv_*` matview'lar (RLS desteklemez → ham matview client rollerinden REVOKE edildi, daima üstündeki view sorgulanır).

## İş Kuralları

**Randevu & Tablet**
- Çakışma kontrolü oda + terapist + cihaz (DB exclusion constraint + `randevu_cihaz_rezervasyon` trigger'ı; trigger'ın gerçek çakışmayı engellediği denenmedi). Grup seansında `max_kapasite`'ye kadar hasta, her birinden 1 hak düşer. İzinli/raporlu ya da işten çıkış tarihi randevu gününden önce olan terapiste randevu yazılamaz (`lib/randevu/terapist-uygunluk.ts`: onaylı `personel_izin_talebi` + `personel_puantaj` izinli/raporlu; periyodikte o günler atlanıp WhatsApp linkiyle raporlanır). Vardiya/çalışma saati kontrolü YOK.
- **Yeni randevuda seçim sırası** (Tek + Periyodik): Hasta → Tedavi → Tarih → Dr/Terapist → Oda → **müsait saat butonları** (08:00-20:00, 30 dk ızgara; terapist VE oda boş, cihazlı adım pencereleri çakışmıyor, seans 20:00'yi aşmıyor, geçmişte değil). Hesap tek yerde: `lib/randevu/musait-saatler.ts` (test'li), veri `queries.ts > useMesgulAraliklar`. Müsaitlik izin/vardiyaya BAKMAZ (engel kaydederken mesajla gelir); çalışma saatleri sabit kodda. Süre `islem_tanimi.sure_dakika` (yoksa adım toplamı, yoksa 30) gizli input'la gider; `cihaz_id` gönderilmez. Periyodikte sonraki dolu haftalar 23P01 ile atlanıp raporlanır. Randevu detay panelindeki `randevuGuncelle` formu eski düzende. Randevu oluşturan 4 ekran ortak `lib/randevu/tedavi-secenekleri.ts` + `lib/personel/atanabilir-terapistler.ts` kullanır.
- **Planlanan iskonto** (yalnız Tek Randevu, Periyodik'te bilinçli yok): Hasta+Tedavi seçilince Tedavi Bedeli + İskonto (₺) + Net Tutar önizlemesi (`islem_tanimi_etkin_fiyat`); `randevu.planlanan_iskonto_tutari`'na yazılır, seans bedeli işlenirken (`randevu_seans_bedelini_isle`) borç satırının `iskonto_tutari`'na aktarılır. Paketli check-in'de kullanılmaz.
- **Check-in bakiyeye dokunmaz** (kullanıcı kararı). Paketsiz seans bedeli YALNIZ seans **tamamlandıktan sonra** Randevu Çizelgesi'nde "Cariye Ekle" (yalnız borç) / "Ödeme Ekle" (borç + ödeme) ile yazılır — ikisi `randevu_seans_bedelini_isle`. Zaten işlenmiş seansta "Ödeme Ekle" hata döner. Durum geçişleri: "Gelmedi" check-in'de düşülen paket hakkını iade eder (gelmeyenden seans düşmek için BEDELLİ İPTAL); bedelsiz iptal de iade eder; "Seansı Bitir" check-in'siz randevuda önce `randevu_gelis_isaretle`'yi çağırır; iptal/tamamlanmış randevuda Geldi/Gelmedi/Ertele/Güncelle/Bitir sunucuda reddedilir (`randevu_kapali`), iptalden çıkış yalnız `randevu_iptal_geri_al` (klinik_admin; düşülen hak iade, yazılan borç silinir, faturalı borçta reddeder).
- **Randevu sonucu Kaydet'le işlenir, iptal bedelli/bedelsiz**: `DurumButonlari` Geldi/Gecikmeli/Gelmedi/Ertelendi/Seansı Bitir'i SEÇER, "Kaydet"le işler. İptal: açıklama + "Bedelli İptal" / "Bedelsiz İptal" (`randevuIptalEt`). Bedelli: uygun paketten FIFO 1 hak (check-in'de düşülmüşse tekrar düşmez), paket yoksa seans bedeli borç ("geç iptal"). Terapist yalnız bedelsiz iptal edebilir. 18 saatten az kala (`lib/randevu/gec-iptal.ts`, SQL `interval '18 hours'` — **ikisi birlikte değişir**) yalnız BİLGİ notu. Portal iptal talebinde açıklama + geç iptal uyarısı; panelde bekleyen talep "Bedelli / Bedelsiz / Reddet" (`iptalTalebiOnayla(talepId, randevuId, bedelli)`). `CREATE OR REPLACE` ile parametre adı değişmez → önce `DROP FUNCTION`. Randevu detay penceresinde Dr/Terapist ve Oda anlık değiştirilebilir; `randevuGuncelle` tüm alanları beklediğinden değişmeyenler GİZLİ input'la aynen gönderilir.
- **Anlık bildirim toast'ları** (`components/panel/randevu-bildirimleri.tsx`): check-in ve ertelemede (terapist kendi randevuları, klinik_admin hepsi; resepsiyon/muhasebe hariç) + paket bitmek üzere (tamamlanma geçişinde yalnız resepsiyon/klinik_admin). `randevu` REPLICA IDENTITY DEFAULT olduğundan geçiş istemcideki id→durum haritasıyla tespit edilir; `/panel/tablet/*`'te çalışmaz. Denenmedi.
- **Paket bitmek üzere alarmı**: `randevuSeansiTamamla` sonrası pakette 1-2 hak kaldıysa (`lib/paket/yenileme-esigi.ts`, 0'da uyarı YOK) action sonucuna uyarı + çizelgede amber kart + toast + hastaya `hasta_paket_seans_azaldi` mesajı (idempotent; hata tamamlamayı engellemez). Hak check-in'de düşer, alarm seans BİTİNCE.
- **Erken check-in tuzağı**: seans geçmişi sorgusu (`useHastaSeansGecmisi`) `baslangic < now()` **YA DA** `durum != planlandi` süzer — zaman filtresi yazarken durumu da hesaba kat.
- Tablet salt-okunur; oda boşken günün son tamamlanan seansının anket QR'ı görünür, yeni check-in'de kaybolur.
- Hedef ama yok: kademeli 48s/24s/2s hatırlatma, QR/NFC check-in, gizlilik modu, tablette dijital onam imzası.

**Cari — borç/ödeme modeli**
- **Borç**: paketsiz seansın tamamlanması sonrası "Cariye/Ödeme Ekle" veya paket satışında `tur='borc'`. Satıra tıklayınca İskonto (₺) + Faturalı girilir; satır HER ZAMAN `tur='borc'` kalır ("kapama"/"ödendi" kavramı YOK, tekrar düzenlenebilir). Bakiye etkisi `-(tutar - iskonto_tutari)`.
- **Ödeme**: bağımsız — `tur='odeme'`, `odeme_id=NULL`, bakiyeyi `+tutar` azaltır. **Borç-ödeme eşleştirmesi YOK**, tek genel bakiye. "Belgelendirme Cinsi" (`belge_turu`) Ödeme Ekle formunda.
- Faturalı ilk işaretlemede `odeme`+`odeme_kalemi`+`odeme_satiri`+`fatura` oluşup borç satırına bağlanır; sonra yeni fatura açılmaz, mevcut güncellenir.
- Paket satışı peşin DEĞİL, borç (`odeme_olustur` paket-only çağrıda `odeme` yaratmaz). Paket kişi kotası dolunca YENİ kişiye satış reddedilir (`kota_doldu`); daha önce almış biri yenileyebilir (ücretsiz sıfırlama yolu yok). İadede kullanılan seanslar tekil fiyattan düşülür. Satılmış paketin tedavisi/seans sayısı değiştirilemez (yol "Tekrarla").
- Ödeme/bakiye kayıt zamanı `lib/datetime.ts > tarihiSimdikiSaatleUTC` ile İstanbul saatine göre kurulur.

**Hasta verisi & yetki**
- Sağlık verisi alanları `ozel_nitelikli_veri_onay_tarihi` rızası olmadan kaydedilmez. Rıza portaldan veya panelden "kağıt form imzalandıysa" butonuyla.

Denenmedi.

**QR / anonim akışlar** (4 statik: Ön Kayıt, Anket, Puantaj Giriş/Çıkış + 1 dinamik seans anketi)

Aç/kapa `ayarlar.qr_kodlari` (anahtar yoksa **açık**); kapalı QR'ı action'lar da reddeder (`qrKoduAktifMi`). Anonim formlarda uzunluk sınırları (uygulama + DB CHECK).

Başka kliniğin QR'ı reddedilir; `sistem_erisimi=false` personel kullanamaz. **Canlıda oturumlu gerçek kayıt denenmedi.** Adım B (`supabase/bekleyen/20261003110000_puantaj_pin_kaldir.sql`: eski PIN RPC'leri + kolonlar DROP) canlı doğrulanmadan UYGULANMAZ.

Personel/portal girişi `lib/auth/giris-hiz-siniri.ts` (hesap başına 15 dk'da 5, IP başına 30 hatalı deneme). Uçtan uca form testi yok.

## Bilinen Tuzaklar (başlıklar)
Hepsi gerçekten yaşandı. **Gerekçeler: `docs/TUZAKLAR.md` — ilgili alana dokunmadan önce aç.**

- **RLS**: INSERT/SELECT/UPDATE/DELETE dörtlüsü tek tek kontrol edilir · `.insert().select()` SELECT policy'sine de tabidir (anon'da id'yi `crypto.randomUUID()` ile sunucuda üret) · policy içindeki `EXISTS` de çağıranın RLS'ine tabidir → `SECURITY DEFINER` helper · kolon düzeyinde GRANT'li tabloya (`klinik_muhasebe_entegrasyonu`, secret kolonu hariç) yeni kolon eklenirse GRANT listesine de eklenmeli.
- **PostgREST**: VIEW'larda embed SESSİZCE boş döner — ayrı çekip `Map`'le birleştir · `.in(col, ids)` GET URL'sine gömülür, uzun listede sorgu SESSİZCE boş/hatalı döner → FK varsa embed, yoksa `parcalara()` (`lib/supabase/sayfali-okuma.ts`) · **`max_rows`=1000**: `.limit()/.range()` olmayan liste 1000'de SESSİZCE kesilir → büyüyen tablolarda `tumSayfalariOku` (sabit sıralama + `.range`, hatada fırlatır); seçim listesi için tüm tabloyu çekme, sunucuda ara.
- **Postgres**: pgcrypto `extensions` şemasında → RPC'lerde `SET search_path = public, extensions` · pooler host `.com` + port 5432 · `is_super_admin()` service-role'de false döner, `auth.role()` de kontrol edilmeli · SELECT trigger yok · **`CREATE OR REPLACE` ile yeni (DEFAULT'lu) parametre eklemek ikinci bir overload yaratır** → PGRST203; önce `DROP FUNCTION eski(imza)` · uygulama kodu yeni migration'a bağlıysa migration canlıya UYGULANMADAN push etme (bkz. memory `migration_before_push`).
- **Banka hesabı bütünlüğü**: havale satırı `banka_hesap_id`'siz hiçbir hesapta görünmez — `banka_hesabi_butunluk` tetikleyicisi (hasta_bakiye_hareket, klinik_harcama, personel_hesap_hareket, klinik_cari_odeme, klinik_kredi_karti_odeme) zorlar; uygulamada `lib/finans/banka-hesabi-kurali.ts`; bağlı kaydı olan hesap silinemez (`banka_hesabi_silme_engeli`). Yeni tabloya `banka_hesap_id` eklersen ikisine de bağla.
- **Next.js**: hub rotasını ALT rotasından `revalidatePath` etmek `isPending`'i sonsuza kadar takıyor · `@supabase/ssr` realtime'a JWT geçirmez, `realtime.setAuth()` şart · dinamik SVG içinde `<title>` hydration mismatch → `aria-label` · `react-hooks/set-state-in-effect` aktif, `useEffect`+`setState` yerine `useQuery`/`useMemo` · Base UI `Select`'te `items` prop'u şart; boş değer için `"__yok__"` sentinel (`CIHAZ_YOK_DEGERI` deseni) · Select'te `value={x || undefined}` kontrolsüz→kontrollü uyarısı verir · route handler'larda `react-dom/server` çalışmaz.
- **Tailwind**: `variant="outline"` üstüne renk bindirirken `!important` şart ve `next build` çıktısından doğrulanmalı · sabit yükseklik + `items-center` + `overflow-y-auto` içeriği yukarı taşırır, `items-start` · responsive eklerken `lg:` önekini unutma.
- **PDF/Puppeteer**: `puppeteer-core` ↔ `@sparticuz/chromium` aynı Chrome milestone'unda ve `--save-exact` (şu an 25.1.0 ↔ 149.0.0) · **yeni PDF route'unu `outputFileTracingIncludes` + `vercel.json > functions`'a ekle**, yoksa prod'da "Could not find Chromium" · `headless:"shell"` · font ve emoji gömülü olmalı · `setContent`, `goto` değil.
- **Zod**: şemada `null` gelebilen alan `z.null()` kabul etmeli (yeni kayıtta adım `id: null` gönderilince "Yeni Tedavi Ekle" bu yüzden çalışmamıştı).
- **Süreç**: "ekranda mantıklı görünüyor" ≠ doğrulandı; tsc/lint/build bu sınıf hataları yakalamaz. Yöntem: psql oturum simülasyonu (`SET LOCAL role authenticated` + `request.jwt.claims` + ROLLBACK), geçici test klinik + gerçek giriş. `npm run lint` baseline 0 hata — yeni hata ekleme.

- **Cron / arka plan işleri**: HTTP route DEĞİL. `scripts/` altında Node betikleri, Windows Task Scheduler çağırır; `bakim_rolu` ile bağlanır (yalnız `klinik` üzerinde SELECT + bakım fonksiyonlarına EXECUTE), klinik başına iş `withTenant` ile. `/api/cron/*` route'ları ve `CRON_SECRET` kaldırılacak.
